Claude Cost Analyzer — what we built and why

Claude usage is moving from a flat subscription to pay-per-token billing. Until now nobody could see what a single conversation, tool call, subagent or hook actually cost. Claude Code already writes every transcript to disk with the exact token count of every API call. This tool reads those files on your own machine and prices them at Anthropic's list rates, so each engineer can see and shape their spend before the switch. Figures below come from the synthetic demo dataset that ships with the app — 62 sessions, 7 fictional projects, 35 days — so this page can be shared. Run it on your own machine to see your own.

What we built one day, September 2026

A local web app — Node 22 with SQLite full-text search, and a React front end — that reads every Claude Code transcript on the machine and turns it into a ledger.

  • Cost per project, conversation, turn, API call, tool call, subagent, workflow run, hook and harness injection.
  • Full-text search across every chat, with each result priced.
  • A month-by-month subscription-versus-API comparison, a budget and a month-end forecast.
  • Insights: cache misses, compactions, expensive tool output, model mix, and what-if pricing.
  • An editable price table, live re-indexing as you work, and CSV/JSON export.

Nothing leaves the machine. The server listens on the loopback address only. No telemetry, no external fonts or scripts, no network calls at all while it runs.

What it revealed whole history, 7 Aug – 9 Sep 2026

  • Long conversations are the bill. $85 1 session ran above 150k average context, at 179.4k tokens on average. Every request re-sends the whole conversation, so cost grows with the length of the chat, not with the work done.
  • Model choice is the biggest lever. $401 cheaper The same tokens priced at Sonnet 5 rates instead of the Opus-class rates actually used: $267 rather than $668. A price swap only — the work might take more turns.
  • Shell output is expensive to keep. $3.14 What Bash output cost purely to stay in the context window afterwards — 14.6% of everything the demo dataset pays to carry tool output. Trimming it, or writing it to a file, cuts that.
  • A third of context cost is text nobody typed. 34% Estimated: under 1% is harness and hook text injected per turn, 33% is the fixed baseline — system prompt, tool definitions, memory files — re-sent on every single call.

The priciest conversation in the demo dataset is a $88.72 session — 705 API calls, 656 tool calls and 4 subagents, active for 4h 09m — the second screenshot below is that conversation, priced by this app.

How to trust the numbers

Exact
Every per-call figure comes from the token counts Anthropic returned and Claude Code wrote down. No sampling, no estimation.
Estimated
Only the split of a call's cost across the things that filled its context — a tool result, a hook, your prompt. Anthropic bills per call, not per tool, so this is a stated model. The app labels every such figure "est." and explains the method on its Methodology page.
Checked
Claude Code keeps its own running cost tally. On every conversation where the two count the same tokens, the money agrees to the cent. Where the tally covers a different span — a resumed or forked chat — the app says which, instead of hiding the gap.
Local
Loopback-only server, no telemetry, no content in the database, transcripts never copied.
Tested
586 unit tests and 101 browser tests, plus an automated accessibility audit (WCAG 2.2 AA) on every page in both light and dark themes.

How to run it

Node 22 or newer. It indexes a few hundred conversations in seconds and opens a browser.

npm install
npm run build
npm start

It reads ~/.claude/projects, the folder Claude Code already writes to. Nothing to configure, no account, no key.

What we suggest next

  • Roll it out to the team. One command per engineer; everyone sees their own spend and nobody's data moves.
  • Set a per-person monthly budget in the app and let the forecast warn before the month ends, not after the invoice.
  • Review the numbers monthly as a team: model mix, session length, and the tools whose output we pay to carry.
  • Decide subscription versus pay-per-token per team, using each team's own measured months rather than a single company-wide assumption.
